# 复杂交互页面中的筛选状态与上下文状态分离实践

**日期**：2026-05-29
**涉及文件**：`source/vue/xzs-student/src/views/knowledge-graph/index.vue`
**影响范围**：AI 学习工作台按钮逻辑、科目切换、右上角状态标签

---

## 1. 问题背景

AI 学习工作台页面同时承担知识点学习、真题讲解、错题回顾、题目粘贴分析等功能。用户可以通过左侧选择科目，也可以点击中间区域的"知识点""真题""错题""粘贴"快捷按钮。

开发过程中发现按钮逻辑存在状态混用，具体表现：

1. 选择知识点后点击真题或错题，按钮下方显示的筛选范围不一致。
2. 点击真题或错题后切换科目，中间区域仍保留旧题目上下文。
3. 点击真题时系统可能自动切换到另一个知识点，用户原先的选择被隐式替换。
4. 右上角状态标签、按钮文案、中间上下文卡片信息不完全一致。

表面是按钮显示错误，本质是页面状态模型设计不清晰。

---

## 2. 原因分析

原页面中 6 个状态变量被混合使用：

| 变量 | 原设计意图 | 实际问题 |
|---|---|---|
| `selectedSubjectName` | 科目筛选 | 与上下文清理耦合不完整 |
| `selectedPoint` | 知识点选择 | 同时承担筛选和展示两个职责 |
| `contextMode` | 上下文类型 | 被当作筛选判断条件，点错题后从 knowledge 变为 question，知识点筛选随之失效 |
| `selectedQuestion` | 当前题目 | 切换科目时未清理 |
| `questionContext` | 题目文本 | 同上 |
| `activeQuickAction` | 按钮高亮 | 部分逻辑中参与了筛选判断 |

核心问题：**没有区分"筛选范围"和"当前展示内容"。**

例如 `contextMode === 'knowledge'` 曾被用来判断是否处在知识点筛选范围。但用户点击错题后，`contextMode` 变成 `question`，此时知识点筛选不应失效。继续用 `contextMode` 判断筛选，导致错题/真题按钮不再按知识点范围查找。

---

## 3. 重构方案：三层状态模型

### 3.1 筛选状态

回答："从哪个范围抽取知识点/真题/错题？"

- `selectedSubjectName` — 科目筛选（宽范围）
- `selectedPoint` — 知识点筛选（窄范围）

只要 `selectedPoint` 存在，真题和错题按钮都严格按照该知识点执行。

### 3.2 上下文状态

回答："中间区域展示什么？AI 围绕什么讲解？"

- `contextMode` — none / knowledge / question
- `selectedQuestion` — 当前展示的真题、错题或粘贴题
- `questionContext` — 当前题目文本

上下文只负责展示和 AI 分析，不决定按钮筛选范围。

### 3.3 UI 状态

回答："哪个按钮高亮？"

- `activeQuickAction` — 仅控制按钮样式

不参与筛选、不参与请求参数、不影响右上角标签。

---

## 4. 主要修改

### 4.1 清理函数去副作用

`clearKnowledgeContext` → `clearKnowledgeFilter`，去掉内部 `saveSelectedPoint()` 调用。所有调用方在动作结束后统一 `saveState()` + `updateWelcome()`，避免保存半完成状态。

### 4.2 科目切换

点击具体科目 = 用户主动切换筛选范围：

- 清空知识点筛选（`clearKnowledgeFilter`）
- 清空非粘贴题目的上下文
- 退出 knowledge 模式

点击"全部" = 仅解除科目限制，保留 `selectedPoint`。

### 4.3 真题按钮

| 条件 | 行为 |
|---|---|
| 有 `selectedPoint` | 只从 `relatedQuestions` 找，找不到提示"暂无关联真题"，不自动换知识点 |
| 无 `selectedPoint` | 遍历 `scopedKnowledgePoints` 找有关联题的知识点 |

删除了通过 `/api/student/question/answer/page` 兜底找真题的 API fallback，真题统一只来自知识图谱关联。

### 4.4 错题按钮

| 条件 | 行为 |
|---|---|
| 有 `selectedPoint` | 只从关联题中找错题，找不到提示"暂无关联错题"，不降级到科目 |
| 无 `selectedPoint` | 按科目范围查找错题 |

关键改动：判断条件从 `contextMode === 'knowledge' && selectedPoint` 改为只看 `selectedPoint`。

### 4.5 粘贴题目

粘贴后调用 `clearKnowledgeFilter()`，避免粘贴题与旧知识点筛选并存导致页面状态混乱。

### 4.6 标签与按钮文案

右上角标签改为上下文优先、简洁表达：

| 场景 | 显示 |
|---|---|
| 粘贴题目 | `上下文 · 粘贴题目` |
| 真题/错题 | `题目 · 计算机组成原理 · 多处理器` |
| 知识点选中 | `知识点 · 多处理器` |
| 仅科目 | `筛选 · 计算机组成原理` |

按钮下方文案：知识点按钮显示当前知识点名或科目，真题和错题按钮统一显示 `selectedKnowledgeScopeText`（`科目 · 知识点`）。

---

## 5. 设计原则

1. **筛选和上下文必须分离。** 筛选决定"从哪里找"，上下文决定"展示什么"。
2. **系统不能隐式替用户改变范围。** 明确失败比暗中成功更可靠。
3. **按钮文案应表达操作范围。** 用户点击前应知道系统会从哪里抽取内容。
4. **UI 高亮不能参与业务逻辑。** `activeQuickAction` 只管样式。
5. **状态清理要集中且可控。** 先完成状态更新，再统一保存。

---

## 6. 验证场景

1. 选"多处理器" → 点错题 → 按钮显示"计算机组成原理 · 多处理器"，错题只从该知识点范围查找。
2. 选知识点 → 点真题，无关联真题时只提示，不自动切换。
3. 未选知识点 → 点真题，可在科目下遍历知识点找到关联真题。
4. 点左侧其他科目 → 旧知识点和题目上下文被清理。
5. 点"全部" → 保留当前知识点。
6. 粘贴题目 → 清空旧知识点，显示粘贴题上下文。
7. 查看错题时点知识点 → 旧题目上下文清空，进入知识点学习状态。

---

## 7. 经验总结

这次问题的根因是状态设计不清晰。前端页面同时存在筛选、上下文、显示、高亮等多类状态时，没有明确分层就会导致旧状态残留、显示不一致和用户操作不可预期。

最终将状态整理为：科目和知识点负责筛选，真题/错题/粘贴负责上下文，按钮高亮只管 UI，标签和文案向用户解释当前状态。页面逻辑更清晰，后续功能扩展也不再容易引发类似问题。
