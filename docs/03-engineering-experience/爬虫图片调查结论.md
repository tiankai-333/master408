# 爬虫图片调查结论

> 日期：2026-05-20 | 背景：爬虫只抓到 7 个图片文件，远少于真题中"如下图所示"暗示的数量

## 根因

原站 `csgraduates.com` 14 个年份页面 **总共只有 17 个 `<img>` 标签**（去重 15 张）。爬虫 `exam_crawler_with_images.py` 通过 `find_all('img')` 抓取，逻辑正确，已全量抓取。

## 为什么"感觉应该有更多图"

原站大量题目含"如下图所示"等文字，但这些 **不是 `<img>` 标签**：

| 形态 | 示例 | 说明 |
|---|---|---|
| HTML `<table>` | 2023-Q19 流水线时序图、Q29 调度表、Q9 散列表 | 原站用表格画图，爬虫不截图 |
| KaTeX 公式 | 全年份大量 `$...$` | 通过 `katex.min.css` + JS 渲染，非图片 |
| 纯文字描述 | "如下图所示" 后跟文字分析 | 原站本身就没配图 |

2023 年页面有 11 处"图/表"文字引用，但只有 1 个 `<img>` + 4 个 `<table>`。其余都是纯文字。

## 原站图片 URL 路径模式

- `/images/{year}_{question_no}.drawio.svg` — 题目级别
- `/images/paper/{year}/{question_no}.drawio.svg` — paper 目录级别

大部分是 `.drawio.svg`（draw.io 矢量图），仅 2023-Q19 是 `.jpg`。

## 已修复：图片在系统中的数据流

1. 爬虫写入 `t_question.images` 列（如 `images/2012/2012_4.svg`）
2. 该列后端 `Question.java` **未映射**，不可读（这是图片不显示的直接原因）
3. 修复方案（`15_embed_question_images.sql`）：将图片路径转为 `<img>` 标签追加到 `title`
4. `04_exam_data.sql` 已同步修改：9 行有图片的题目直接带 `<img>` 标签 + 路径修正为正斜杠
5. 前端 `v-html="question.title"` 渲染
6. Nginx 新增 `location /images/` 提供静态文件服务
7. 图片文件从 `crawler/images/` 复制到 `deploy/static/images/`

## 补充图片的可行方案

当前爬虫无法获取更多图片（原站没有）。如需补充：

- 从 PDF 真题手动截图
- 使用 draw.io 重绘关键图表
- 寻找其他有完整图片的题库数据源
